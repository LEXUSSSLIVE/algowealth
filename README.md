# AlgoWealth

Private wealth tracking for iOS: a React Native app backed by a FastAPI service. Tracks a multi-bank investment portfolio (holdings, allocations, per-account balances), live market quotes and watchlists, and ships a built-in blog with a web admin panel.

## Features

**Mobile app (Expo / React Native)**
- Home: total balance with period chart, favorites with sparklines, latest posts
- Portfolio — Holdings: per-account cards with day-over-day change, bank/type filters, balance chart
- Portfolio — Allocations: donut by instrument type, filterable instrument list
- Watchlist: live quotes with auto-refresh, swipe-to-delete with undo, search with debounce
- Stock screen: price chart with periods, 14 fundamental market stats
- Blog: article feed with categories, rich-text posts (headers, lists, images, PDF attachments)
- Settings: password change, account deletion; JWT auth with silent token refresh

**Backend (FastAPI)**
- JWT auth (short-lived access + refresh, token-version invalidation on password change)
- Proxy over an external portfolio data API — the API key never reaches the client
- Quotes and fundamentals via yfinance with caching
- Web admin panel: CSV portfolio uploads per user, user management, blog CRUD (editor.js), password reset queue with Telegram notifications

## Architecture

```
iOS app (Expo)
   │  HTTPS + JWT
   ▼
FastAPI backend ──── SQLite (users, watchlists, posts, quote cache)
   │  server-side API key
   ▼
Portfolio data API (external Go service, not included)
```

The backend expects an external portfolio API that stores per-group portfolio snapshots uploaded as CSV ([finance_track_server](https://github.com/iovanom/finance_track_server)). Registration is invite-only by design: users are created through the admin panel, each bound to a data group so every user only ever sees their own portfolio.

## Project structure

```
app/       Expo app (expo-router, TypeScript)
backend/   FastAPI service + admin panel (Jinja2), pytest suite
deploy/    docker-compose, nginx config, demo data generator
```

## Getting started

### Quick start with demo data

`deploy/demo/` ships a ready-made dataset: an app database with an admin user, 10 published blog posts with covers and PDF attachments, a seeded watchlist, and a year of daily portfolio snapshots (fictional US banks and instruments). Preload it **before** the first `docker compose up`, so the data directory is created with your permissions:

```bash
cd deploy
cp .env.example .env                # fill in the secrets
mkdir -p data
cp demo/app.db data/app.db
cp -r demo/uploads data/uploads
docker compose up -d --build
tar xzf demo/history.tar.gz         # portfolio history → upload into the Go service
python3 upload_history.py --api http://localhost:8088/api \
    --key <GO_API_KEY> --group demo-portfolio --dir demo_history
```

Sign in as **demo@algowealth.app / algowealth-demo** (admin). The app then shows a living portfolio — balance chart across all periods, day-over-day changes on account cards, allocation donut — and a populated blog. The dataset is reproducible from scratch with `gen_demo_history.py` (seeded RNG) and `seed_blog_demo.py` if you prefer generating your own.

### Clean start

Bring up an empty backend and create your own admin user:

```bash
cd deploy
cp .env.example .env
docker compose up -d --build
docker compose exec api python cli.py create-user \
  --email you@example.com --group-id my-portfolio --role admin
# the generated password is printed to the terminal
```

Registration is invite-only, so every user is created this way (or later through the admin panel). Portfolio data arrives by uploading a CSV for the user; `deploy/sample.csv` shows the expected columns (one full day: 33 positions across 10 banks).

### Admin panel

`http://localhost:8100/admin` — sign in with any `role=admin` user of the app. Four sections:

- **Upload** — upload a portfolio CSV for a chosen user (optionally backdated)
- **Users** — create users, reset passwords, delete accounts, purge orphaned portfolio rows
- **Blog** — create and edit posts in a rich-text editor (cover image, PDF attachment, draft/publish)
- **Password resets** — queue of reset requests from the app (optional Telegram notification)

### App

Set your API URL in `app/src/api/config.ts`, then:

```bash
cd app
npm install
npx expo start          # add --tunnel to test on a phone outside your network
```

Run it on a device with the [Expo Go](https://expo.dev/go) app (SDK 54) by scanning the QR code from the terminal, or press `i` to open the iOS simulator. For a standalone TestFlight/App Store build use [EAS Build](https://docs.expo.dev/build/introduction/) — `eas.json` is already configured.

All portfolio data shown in screenshots and generated by the demo tooling is synthetic.
